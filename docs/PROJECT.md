# MyWeb: contexto de producto

## Qué es MyWeb

MyWeb es la web profesional y portfolio de Roger Magrià, compositor y sound designer. Su foco principal es ofrecer música original, sound design y audio para trailers a videojuegos indie.

La web no es únicamente un portfolio ni gira alrededor del estimador. Es una experiencia comercial completa que debe explicar rápidamente qué hace Roger, demostrar la calidad y fiabilidad de su trabajo y convertir el interés de un posible cliente en una conversación personal por email.

## Objetivo principal

La acción principal deseada es que un visitante con un proyecto adecuado contacte con Roger.

El recorrido ideal es:

1. Entender inmediatamente que la web ofrece audio profesional para videojuegos indie.
2. Escuchar y ver trabajos relevantes.
3. Comprender los servicios, el proceso y la forma de colaboración.
4. Ganar confianza mediante proyectos reales, atribuciones precisas y testimonios auténticos.
5. Contactar con Roger mediante un formulario o solicitar una revisión personal desde una herramienta de planificación.
6. Continuar la conversación por email.

Las herramientas gratuitas —el estimador de presupuesto actual y un posible estimador de scope futuro— apoyan este recorrido. Aportan claridad y ayudan a iniciar una conversación, pero no son el centro del producto.

## Audiencia principal

MyWeb está pensada para:

- Estudios indie pequeños.
- Equipos de pocas personas.
- Desarrolladores en solitario.
- Personas o empresas pequeñas que están creando un videojuego y necesitan ayuda de audio.
- Proyectos con presupuestos más limitados que una gran producción, pero que valoran un resultado profesional.
- Clientes de cualquier país y para cualquier género de videojuego.

El posicionamiento principal debe seguir siendo game audio para videojuegos indie. Roger también tiene experiencia real en apps, cortometrajes, trailers y otros proyectos audiovisuales, que puede mencionarse como contexto secundario sin diluir el foco principal.

## Actividad profesional

Roger puede participar en distintas combinaciones según el proyecto:

- Música original.
- Sound design.
- Música y sound design juntos.
- Audio para trailers y piezas promocionales.
- Preparación y entrega de assets.
- Soporte técnico o de implementación cuando el alcance lo requiere.

La web nunca debe dar a entender que Roger realizó todo el audio de un proyecto cuando su participación fue parcial o compartida.

## Experiencia que debe ofrecer la web

La experiencia debe sentirse:

- Clara desde el primer contacto.
- Profesional y premium sin parecer inaccesible para un equipo indie.
- Visual y sonora, utilizando proyectos, música y vídeo como prueba del trabajo.
- Fiable, honesta y específica sobre la contribución realizada.
- Fácil de recorrer, con una progresión natural hacia el contacto.
- Internacional; el contenido público actual está escrito principalmente en inglés.
- Responsive y usable tanto en escritorio como en móvil.

No se busca presionar al visitante ni convertir la web en una secuencia agresiva de captación. Primero se muestra valor; después se ofrece un siguiente paso claro.

## Áreas principales

### Home

Página principal de posicionamiento y conversión. Presenta servicios, trabajo seleccionado, showreel, experiencia, problemas que resuelve el audio, proceso, testimonios, información personal, FAQ y contacto.

La estructura y el diseño del frontend están aproximadamente al 90%. Quedan principalmente contenidos finales: reemplazar algunos vídeos, ampliar Selected Work, revisar afirmaciones y terminar la captación real.

### Projects

Portfolio de proyectos reales de cliente. No debe incluir las demos musicales de portfolio como si fueran videojuegos o encargos reales.

La página actual es una base temprana. Debe repensarse y combinar, cuando se defina la tarea, elementos útiles de `projects.html` y `projects_2.html`.

### Páginas individuales de proyecto

Cada proyecto relevante debe poder abrir una página completa propia. `case-study.html` es el prototipo actual de ese formato, aunque su contenido todavía es provisional.

Estas páginas deben servir para explicar el proyecto, contexto, contribución de Roger, proceso, música, sound design, materiales, vídeos o trailers, resultados y testimonios cuando existan.

### Process

Debe explicar de forma útil cómo se trabaja con Roger y qué puede esperar un cliente. La versión actual es una demo temprana; su contenido definitivo todavía no está decidido.

### Budget

Contiene el Game Audio Budget Estimator. Su frontend y motor están avanzados, aproximadamente al 90% desde el punto de vista visual y de cálculo. Falta completar captación, privacidad, envío y backend.

### Resources

Debe convertirse en un área útil de guías y herramientas para equipos indie. La versión actual es una demo visual y de contenido. Su alcance definitivo todavía debe definirse.

### Contacto

Es el destino principal del funnel. Debe permitir que un posible cliente envíe contexto suficiente para que Roger responda personalmente por email. El formulario visible actual todavía no realiza envíos.

## Principios de producto

- Claridad antes que complejidad.
- Prueba real antes que afirmaciones genéricas.
- Atribución honesta de cada trabajo.
- Valor antes que fricción o captación.
- Herramientas que ayuden al cliente a entender su proyecto, no simples trucos de lead generation.
- Presentación premium compatible con presupuestos y equipos indie.
- Evolución progresiva: una función bien definida y comprobada cada vez.
- GitHub como centro del historial y de la versión oficial del proyecto.

## Fuera del alcance actual

Todavía no están decididos:

- El proveedor de hosting definitivo.
- El backend y la base de datos.
- El proveedor de email o formularios.
- Un CMS o sistema de gestión de proyectos.
- Analítica y seguimiento de conversiones.
- El contenido definitivo de Process y Resources.

Estas decisiones no deben inventarse ni implementarse sin una tarea específica.
